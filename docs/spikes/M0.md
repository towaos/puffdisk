# M0 検証スパイクの結果

DESIGN.md 13.1 の検証項目の結果。実施日 2026-10-28、macOS 27.2（Apple Silicon）、Xcode 27.1。

CLI のスパイクは `Packages/PuffdiskCore` で `swift run puffdisk-spikes <コマンド>`、アプリ内のスパイク（S1・S2）はデバッグビルドのポップオーバーから実行する。

| # | 項目 | 結果 | 設計への反映 |
|---|---|---|---|
| S1 | Downloads 内のファイルの `kMDItemLastUsedDate` | **取れるが、50 件中 17 件だけ** | 7.4: 代わりの判定（追加日・更新日）が主な経路になる前提にする |
| S2 | Downloads → Application Support へ `rename` で移動・復元 | **できる**。同じボリューム、隔離フォルダの権限 700 | なし |
| S3 | カタログの各パスが実機で正しいか | **一部違う**（下記） | 7.2・7.3 を修正 |
| S4 | FSEvents の監視と指定IDからの再生 | **できる** | なし |
| S5 | `getattrlistbulk` と `FileManager` の速さ | **getattrlistbulk が 2.5〜3.5倍速い** | 9.3: `getattrlistbulk` を採用 |
| S6 | `isUbiquitousItem` でクラウド同期を判定 | **一部のみ確認**（下記） | 別の環境で追加確認 |
| S7 | アイコン幅の変更、ノッチ付き Mac での見え方 | **問題なし**（スライダーで5段階を切り替え、他の項目のちらつき・ノッチでの隠れなし） | なし（16〜22pt のまま） |

## S3 カタログ

ツール自身が報告する場所との照合:

| ツール | 報告された場所 | カタログ |
|---|---|---|
| npm（`npm config get cache`） | `~/.npm` | 一致（`_cacache` を対象） |
| Homebrew（`brew --cache`） | `~/Library/Caches/Homebrew` | 一致 |
| Go（`go env GOCACHE GOMODCACHE`） | `~/Library/Caches/go-build`、**`~/.go/pkg/mod`** | **モジュールキャッシュが違う**。`go env -w GOPATH=~/.go` の設定が `~/Library/Application Support/go/env` に保存されていた。3.8GB を見落とす |
| pip（`pip3 cache dir`） | `~/Library/Caches/pip` | 一致 |
| uv・pnpm・Yarn・Bun・Cargo | 未インストール | 確認できず |

シェルの環境変数でキャッシュの場所を変えているものはなかった。ただし Go のように**ツール自身の設定ファイル**で変えている場合がある。

走査して分かったこと:

- **DerivedData の中にプロジェクトではないフォルダがある**: `ModuleCache.noindex`（109MB）、`SymbolCache.noindex`、`SDKStatCaches.noindex`、`CompilationCache.noindex`。`info.plist` がないので 7.3 の判定ができない。いずれも Xcode が作り直す共有キャッシュ。
- **「〜ごと」の単位の直下にファイルがある**: Hugging Face の `hub/version.txt`。サブフォルダだけを単位にする必要がある。
- 実測（このマシン）: Homebrew 4.66GB、Gradle（wrapper）1.13GB、npm 1.11GB、go-build 756MB、DerivedData 693MB、node-gyp 68MB。Go モジュールキャッシュ（`~/.go/pkg/mod`）3.8GB はカタログの外。

## S4 FSEvents

`kFSEventStreamCreateFlagFileEvents` で、ファイルの作成・削除・サブフォルダの作成を受け取れた。開始時のイベントIDを保存し、変化のあとでそのIDから再生すると、すべての変化が `HistoryDone` の前に届いた。イベントIDの順序は前後することがある（同じ項目の変化はまとめられる）。

## S6 クラウド同期

- `~/Library/Mobile Documents/com~apple~CloudDocs`（iCloud Drive）: `isUbiquitousItem = true`
- `~/Desktop`・`~/Documents`: `isUbiquitousItem = nil`。このマシンでは iCloud の「デスクトップと書類」がオフのため、オンのときの値は未確認
- `~/Library/CloudStorage`: 空（Dropbox・Google Drive 等なし）。File Provider の判定は未確認

→ 「デスクトップと書類」がオンの環境と、File Provider（Dropbox 等）がある環境で追加確認が要る。

## S8 Spotlight

`~/Library/Application Support/Puffdisk-spike/` の下に3つのフォルダを作り、同じトークンを含む名前のファイルを置いて `mdfind -name` で調べた。

| フォルダ | 結果 |
|---|---|
| `Control/`（何もしない） | 索引された |
| `Test.noindex/` | **索引されなかった** |
| `NeverIndex/`（`.metadata_never_index` を置く） | 索引された（効かない） |

## S1 最終使用日

Downloads の許可ダイアログを許可したあと、先頭 50 件で `MDItemCopyAttribute(kMDItemLastUsedDate)` を読んだ。値があったのは 17 件（34%）。Finder などから開いていないファイルには値がない。

## S2 隔離の往復

Downloads にテストファイルを作り、`~/Library/Application Support/Puffdisk/Spike.noindex/`（権限 700 で作成）へ `rename` で移し、また `rename` で戻した。ボリュームIDは一致し、移動・復元とも成功した。macOS の許可（TCC）は Downloads に対する1回だけで、Application Support 側には不要だった。
